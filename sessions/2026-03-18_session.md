## Логика системы

```
[Пользователь в TG боте]
         │
         ├── /add_niche аренда квартир Москва
         │     └── WF1: AI профиль ниши (Gemini)
         │           → поиск каналов (Python /search_channels)
         │           → скоринг каналов (Gemini)
         │           → score >= 0.8 → approved
         │           → score 0.5-0.8 → pending (ручная проверка)
         │           → score < 0.5 → auto_rejected
         │           → сохранить в sources
         │
         ├── /approve_sources
         │     └── WF1: показывает pending каналы с кнопками ✅/❌
         │           → approve → status=approved
         │           → reject → status=rejected
         │
         ├── /start_parse [диалог: дни + ключевые слова]
         │     └── WF1 → webhook → WF2
         │           → читает approved каналы
         │           → Python /parse (до 5 мин)
         │           → фильтр постов
         │           → Gemini анализ каждого поста
         │           → is_lead + priority A/B/C
         │           → сохранить в leads
         │           → 🔥 горячий лид A → мгновенное уведомление
         │           → итоговый отчёт (один на всё)
         │
         ├── /leads
         │     └── WF1: показывает топ-5 горячих лидов из таблицы
         │
         ├── /send_leads
         │     └── WF1 → webhook → WF3 (smart-lead-trigger)
         │           → читает A-лиды (status=new) из leads
         │           → показывает превью топ-3
         │           → ты подтверждаешь → webhook → WF3 (smart-lead-execute)
         │                 → Gemini генерирует персональное сообщение
         │                 → Python /send_message
         │                 → status=contacted
         │                 → итоговый отчёт рассылки
         │
         ├── /niches — список активных ниш
         └── /status — статистика системы
```

## Воркфлоу 2 — ⚙️ AI Parser + Поиск Лидов

**ID оригинала:** `jxbNxW6a0jWccvmk`
**Файл исправленный:** `WF2_ai_parser_FIXED.json`

### Триггеры

| Тип | Path | Описание |
|-----|------|---------|
| Webhook POST | `ai-parse-trigger` | Вызов из WF1 `/start_parse` |
| Schedule | каждые 6 часов | Автоматический запуск |

### Входные параметры

```json
{
  "days_back": 7,
  "keywords": ["слово1", "слово2"],
  "chat_id": "7984101063"
}
```

### Цепочка обработки

```
Webhook / Schedule
  → Ответить на вебхук (немедленно, не блокирует)
  → Нормализовать входные данные
  → [параллельно] Получить источники (approved) + Получить ниши
  → Сформировать запрос парсера
  → Есть каналы?
    [нет] → Уведомить об ошибке в TG
    [да]  → Вызов парсера Python /parse (timeout 5 мин)
          → Подготовить лиды
          → Фильтр пустых лидов (text + post_url не пустые)
          → [для каждого поста] Claude анализ лида (Gemini)
          → Парсинг AI ответа (.item.json — текущий лид!)
          → Сохранить лид (leads, appendOrUpdate по post_url)
          → Горячий лид A?
            [да] → Уведомление горячего лида в TG
                 → Merge (input 1)
            [нет]→ Merge (input 0)
          → Агрегировать все лиды (ОДИН раз после всех)
          → Отправить итоговый отчёт в TG
```

### AI анализ лида — формат ответа

```json
{
  "is_lead": true,
  "priority": "A",
  "reason": "объяснение 1-2 предложения",
  "intent": "buying|asking|info|other",
  "urgency": "high|medium|low"
}
```

### Поля таблицы Telegram_Leads_Template

| Поле | Описание |
|------|---------|
| post_url | Ключ (уникальный) |
| channel | Username канала |
| author | Имя автора поста |
| username | @username автора |
| text | Полный текст поста |
| date | Дата поста |
| views | Просмотры |
| is_lead | true/false |
| ai_priority | **A** / B / C |
| ai_reason | Причина приоритета |
| ai_intent | buying/asking/info/other |
| ai_urgency | high/medium/low |
| status | **new** / contacted / message_sent |
| analyzed_at | ISO дата анализа |

### Исправленные баги WF2

| # | Баг | Исправление |
|---|-----|------------|
| 1 | Webhook path несоответствие | `ai-parse-trigger` (без -v2) |
| 2 | `.first().json` → все лиды = данные лида #1 | `.item.json` — текущий лид |
| 3 | Отчёт N раз (по лиду) | Merge-нода восстановлена |
| 4 | Читал `n.keywords` → пустые ключи | Исправлено на `n.ai_keywords` |

## Воркфлоу 3 — 💬 Smart Lead ПИШЕТ ЛИДАМ V2

**ID оригинала:** `thesORWPbtiJmD1u`
**Файл исправленный:** `WF3_smart_lead_FIXED.json`

### Два webhook-триггера

| Webhook | Path | Назначение |
|---------|------|-----------|
| Превью | `smart-lead-trigger` | Показать список лидов перед отправкой |
| Execute | `smart-lead-execute` | Реально отправить сообщения |

### Цепочка ПРЕВЬЮ

```
POST /smart-lead-trigger
  → Нормализовать chat_id
  → Получить A-лиды (ai_priority=A, status=new) из leads
  → Сформировать превью (топ-3 с username)
  → Есть лиды?
    [нет] → "Нет горячих лидов" в TG
    [да]  → Отправить превью в TG
            (пользователь видит список и принимает решение)
```

### Цепочка EXECUTE

```
POST /smart-lead-execute
  → Нормализовать chat_id
  → Получить A-лиды (ai_priority=A, status=new) из leads
  → Фильтровать лидов с username
  → Есть лиды?
    [нет] → "Нет лидов" в TG
    [да]  → [для каждого лида]:
            Gemini генерирует персональное сообщение
            → Извлечь сообщение (.item.json — текущий лид!)
            → Python /send_message
            → Проверить результат (.item.json — текущий лид!)
            → Обновить status → contacted
          → Собрать статистику
          → Итоговый отчёт в TG
```

### Исправленные баги WF3

| # | Баг | Исправление |
|---|-----|------------|
| 1 | `" approved"` пробел в фильтре | `"approved"` без пробела |
| 2 | `.first().json` → сообщения для всех от лида #1 | `.item.json` |
| 3 | `.first().json` в проверке результата | `.item.json` |
| 4 | `Записать лиды` в таблицу sources | Исправлен ID → leads таблица |
| 5 | Превью запускало парсер заново | Читает из готовой таблицы лидов |
| 6 | `\n` в фильтре ниши | Убран trailing newline |
| 7 | `channel_url.replace()` без null-check | Добавлена проверка `|| ''` |
