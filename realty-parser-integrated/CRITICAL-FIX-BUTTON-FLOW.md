# 🔧 КРИТИЧЕСКОЕ ИСПРАВЛЕНИЕ: Правильный поток для кнопок

## ❌ Проблема

**Симптом:** При нажатии на любую кнопку (Авито, ЦИАН и т.д.) снова и снова выскакивает таблица с кнопками, но ничего не происходит дальше ноды Switch.

**Причина:** Неправильный Data Flow

### Старый (неправильный) поток:

```
📱 Telegram Trigger
    ↓
Send a text message (ВСЕГДА показывает кнопки!)
    ↓
Switch
```

**Что происходило:**
1. Пользователь нажимает кнопку "🏢 Авито"
2. Telegram Trigger получает callback_query
3. Идёт в "Send a text message" → показывает кнопки СНОВА ❌
4. Идёт в Switch
5. НО Switch получает данные от "Send a text message" node, а НЕ от Telegram Trigger!
6. Switch не может найти callback_query.data → не срабатывает
7. Ничего не происходит ❌

---

## ✅ Решение

### Новый (правильный) поток:

```
📱 Telegram Trigger
    ↓
❓ Это message или callback?
    ↓                    ↓
  true               false
    ↓                    ↓
Send a text      ✅ Answer Callback Query
message               +
(показать           Switch
 кнопки)              ↓
                   Parsers
```

### Как это работает:

**Сценарий 1: Пользователь отправляет /start**
```
1. Telegram Trigger получает message
2. IF node: $json.message существует? → true
3. → Send a text message (показывает 4 кнопки)
4. КОНЕЦ (НЕ идёт в Switch)
```

**Сценарий 2: Пользователь нажимает кнопку "🏢 Авито"**
```
1. Telegram Trigger получает callback_query (data: "avito")
2. IF node: $json.message существует? → false
3. → Answer Callback Query (убирает "часики" загрузки)
4. → Switch получает ОРИГИНАЛЬНЫЕ данные от Telegram Trigger
5. Switch: $json.callback_query.data === "avito" → true
6. → Запуск Авито
7. → Результаты → Google Sheets → Telegram уведомление
```

## 🔧 Изменения в workflow

### 1. Добавлен IF node "❓ Это message или callback?"

**Параметры:**
```json
{
  "conditions": {
    "string": [
      {
        "value1": "={{ $json.message ? 'message' : 'callback_query' }}",
        "operation": "equals",
        "value2": "message"
      }
    ]
  }
}
```

**Логика:**
- Проверяет существует ли `$json.message`
- Если да → это текстовая команда (/start)
- Если нет → это нажатие кнопки (callback_query)

---

### 2. Добавлен Answer Callback Query node

**Параметры:**
```json
{
  "resource": "callback",
  "operation": "answerQuery",
  "queryId": "={{ $json.callback_query.id }}",
  "additionalFields": {
    "text": "✅ Запускаю..."
  }
}
```

**Назначение:**
- Отправляет подтверждение Telegram API
- Убирает "часики" загрузки у пользователя
- Показывает уведомление "✅ Запускаю..."

---

### 3. Изменены connections

**БЫЛО:**
```json
"📱 Telegram Trigger": {
  "main": [[ { "node": "Send a text message" } ]]
},
"Send a text message": {
  "main": [[ { "node": "Switch" } ]]
}
```

**СТАЛО:**
```json
"📱 Telegram Trigger": {
  "main": [[ { "node": "❓ Это message или callback?" } ]]
},
"❓ Это message или callback?": {
  "main": [
    [{ "node": "Send a text message" }],  // true path
    [
      { "node": "✅ Answer Callback Query" },  // false path
      { "node": "Switch" }
    ]
  ]
},
"Send a text message": {
  "main": [[]]  // Больше НЕ идёт в Switch
},
"✅ Answer Callback Query": {
  "main": [[]]  // Только отвечает на callback
}
```
